# FAtiMA reverse engineering for Matrix Affective Engine

Status: first-pass architectural extraction

## Source

Primary reference: GAIPS/FAtiMA-Toolkit, Apache-2.0.

The toolkit exposes separate assets for Emotional Appraisal, Emotional Decision Making, Social Importance, Role Play Character, World Model and Autobiographic Memory. For Matrix we do not plan to import the complete architecture. The goal is selective reuse/reimplementation with a Kotlin/Android-first contract.

## First findings

### 1. Event -> appraisal -> affect is directly reusable as an architectural pattern

FAtiMA's EmotionalAppraisalAsset processes world events, records the event, updates the knowledge base when the event represents a property change, builds an appraisal frame, derives appraisal variables, and finally derives emotions.

Matrix mapping:

WorldEvent / TypedClaim
  -> AffectiveEvent
  -> AppraisalFrame
  -> AffectDerivation
  -> AffectiveStateDelta

Decision: ADAPT / REIMPLEMENT IN KOTLIN.

Reason: the separation of appraisal derivation from affect derivation is useful and diagnostic, but the C# implementation depends on FAtiMA-specific KnowledgeBase, AutobiographicMemory and WellFormedNames abstractions that we do not want to import into Matrix.

### 2. Emotional state with threshold + decay + mood is highly reusable conceptually

FAtiMA's ConcreteEmotionalState keeps a pool of active emotions, applies per-emotion threshold and decay, aggregates/reappraises emotions generated by the same cause, updates mood when a new emotion is admitted, and removes emotions when decay makes them irrelevant.

Matrix mapping:

ActiveEmotion {
  type
  intensity
  causeId
  createdAt
  decay
  threshold
}

AffectiveState {
  activeEmotions
  mood
  persistentAffectByEntity
}

Decision: ADAPT.

We should preserve:
- per-emotion threshold;
- per-emotion decay;
- cause linkage;
- reappraisal of the same cause;
- mood influence on emotion intensity;
- deterministic expiration of weak emotions.

We should NOT copy:
- FAtiMA's memory ownership model;
- its event-name encoding;
- its complete OCC emotion taxonomy;
- direct persistence inside appraisal.

### 3. Cause linkage is important for Matrix memory

FAtiMA links an active emotion to the autobiographical event that caused it. This is directly aligned with Matrix causal trace requirements.

Matrix should preserve a causal chain such as:

WorldEvent/TypedClaim
  -> appraisal result
  -> emotional delta
  -> mood/persistent-affect delta
  -> behavior/decision
  -> optional AffectiveMemoryCandidate

Decision: ADOPT AS CONTRACT.

The affective system must never save memory directly. It can only emit AffectiveMemoryCandidate for Memory Admission.

### 4. Mood should remain separate from persistent feelings toward an entity

FAtiMA already separates active emotions and mood. Matrix needs one additional layer that FAtiMA does not provide exactly as required:

PersistentAffect(entity):
- trust
- attachment
- resentment
- admiration
- aversion
- attraction-related affect if required by game design

This is not the canonical relationship state. Relationship state remains owned by the app/world engine.

Decision: MATRIX EXTENSION.

### 5. Social Importance is useful as a reference, not as the canonical relationship engine

FAtiMA contains a separate SocialImportance asset based on attribution rules. This is relevant for perceived social standing/appropriateness, friendship/romance reasoning and social behavior.

Matrix already has a canonical relationship state supplied by the app. Therefore Social Importance must not become a second authoritative relationship system.

Possible reuse:
- rule pattern for perceived social importance;
- attribution rules;
- social appropriateness signals for Behavior Engine.

Decision: REFERENCE_ONLY / PARTIAL_REIMPLEMENT.

### 6. Appraisal rules are a strong candidate for reuse

FAtiMA models appraisal rules around:
- event pattern;
- target;
- appraisal variables;
- logical conditions evaluated against beliefs.

Matrix adaptation:

AppraisalRule {
  eventPredicate
  targetSelector
  conditions
  outputs
}

where outputs are a small fixed set of appraisal dimensions rather than the full FAtiMA/OCC stack.

Recommended Matrix appraisal dimensions for the first implementation:
- relevance
- desirability / goal congruence
- agency / accountability
- controllability
- novelty
- socialImpact

Decision: ADAPT.

## What to copy/reuse vs avoid

| FAtiMA concept | Matrix decision | Rationale |
|---|---|---|
| Separate appraisal derivation / affect derivation | ADOPT | Clean causal and diagnostic boundary |
| Appraisal rules with event + conditions + values | ADAPT | Avoids inventing a rule engine from zero |
| ActiveEmotion with threshold/decay | ADAPT | Small, deterministic, proven pattern |
| Mood influenced by emotions and decaying over time | ADAPT | Fits Luna's medium-term affect |
| Emotion cause linked to autobiographic event | ADOPT AS CONTRACT | Critical for causal trace and affective memory |
| Full OCC taxonomy | REFERENCE_ONLY | Too large for first Matrix implementation |
| FAtiMA KnowledgeBase | DO NOT ADOPT | Matrix already has TypedClaim/Authority/Memory architecture |
| FAtiMA AutobiographicMemory as persistence authority | DO NOT ADOPT | Would duplicate Matrix Memory Admission/Repository |
| Social Importance as relationship authority | DO NOT ADOPT | App/World owns canonical relationship state |
| Social attribution rules | PARTIAL_REIMPLEMENT | Useful behavioral signal |
| Emotional Decision Making as full action selector | REFERENCE_ONLY for now | Matrix Behavior/Decision architecture must remain canonical |

## Proposed Matrix Affective contract v0

Inputs:
- WorldEvent and/or validated TypedClaim
- canonical World/App state
- current AffectiveState
- personality/persona constants
- optional relevant memories returned through read-only retrieval

Processing:
1. Build AffectiveEvent.
2. Evaluate appraisal rules.
3. Produce AppraisalFrame.
4. Derive zero or more emotion candidates.
5. Apply disposition threshold and intensity modulation.
6. Update active emotions and mood.
7. Update persistent affect toward relevant entities only when evidence crosses a consolidation threshold.
8. Emit diagnostics and optional AffectiveMemoryCandidate.

Outputs:
- AffectiveStateDelta
- BehaviorSignals
- AffectiveMemoryCandidate? 
- causal diagnostic trace

Explicit non-responsibilities:
- no direct memory persistence;
- no canonical relationship transition;
- no final dialogue generation;
- no authority resolution;
- no direct World Truth mutation.

## Initial recommendation

Do not port FAtiMA wholesale.

Create a compact Matrix-native implementation that copies/adapts the proven mechanics:

FAtiMA appraisal rules
+ FAtiMA threshold/decay/reappraisal
+ FAtiMA mood pattern
+ FAtiMA cause linkage
+ Matrix persistent-affect extension

This is currently the strongest reuse-first path because it preserves the useful research-backed machinery without importing FAtiMA's parallel knowledge/memory architecture.
